# AI英语课策划-多Agent协作设计

> 配套文档：《AI英语课策划.md》（核心思想：图片+声音双模态、不引入拼写、对话式学习、Agent 自我进化）

## 1. 设计原则

1. **实时路径单 Agent 作战**：语音对话延迟预算 <1s（超过 2s 学生即感觉卡壳），任何多 Agent 串行都会叠加延迟，因此课中只允许 Tutor 一个 Agent 面对学生。
2. **多 Agent 协作只发生在课前/课后（非实时路径）**：备课、评估、进化均为分钟级延迟，可以放开协作。
3. **同步点固定**：课前产出教案包、课后更新学生画像；课中不等待任何其他 Agent。

## 2. 角色划分（职责单一）

| Agent | 职责 | 出现时机 | 延迟要求 |
|---|---|---|---|
| **Tutor（陪练）** | 唯一面对学生：对话、接话、纠音、控难度、调整聊天气氛 | 课中实时 | ⚡ <1s |
| **Content Curator（内容策展）** | 把影视拆成图片/片段/练习点，产出本课素材包 | 课前离线 | 分钟级 |
| **Assessor（评估员）** | 读对话记录 + 事件日志，评估发音/理解/进步，更新学生画像 | 课后异步 | 分钟级 |
| **Adapter（课程编排）** | 根据画像调整教法、难度、性格、选材方向 | 低频（每日/每周） | 无感 |
| **Motivator（激励）** | 金币结算、进度播报、情感反馈 | 事件触发 | 秒级，尽量规则化 |

**Tutor 是唯一出现在"舞台"上的 Agent，其他都是后台专家。**

## 3. 协作模式：黑板 + 流水线

```
课前:  Content Curator ──写──▶ 📋教案包(素材+练习点)
                                  │
课中:  Tutor 读教案包，独立作战 ◀──┘  ← 实时路径，只有它一个
        │  (可挂轻量工具：查词、切片段、查画像)
        ▼
课后:  Assessor 读对话记录+事件日志 ──写──▶ 🧠学生画像(共享黑板)
                                  │
       Adapter 读画像 ──▶ 调整下一课教案方向、难度、性格
```

- 各 Agent **只读写自己的字段**（Assessor 写能力、Tutor 读兴趣），避免并发写冲突。
- 学生画像是共享黑板，是策划第 5 点「AI 越来越懂用户」的落点。

## 4. 学生画像（共享黑板）数据结构

| 模块 | 字段示例 | 谁写 | 谁读 |
|---|---|---|---|
| 能力图谱 | 发音/词汇/句式/听力 各维度水平（如 0-10） | Assessor | Tutor、Adapter |
| 兴趣偏好 | 喜欢哪类影视、哪些话题聊得开 | Assessor | Tutor、Curator |
| 性格匹配 | 幽默度、严格度、闲聊浓度 | Adapter | Tutor |
| 记忆 | 学过什么、常错什么、上次聊到哪 | Assessor | Tutor、Adapter |
| 基线数据 | 答题用时基线、正确率基线（供观测解读用） | Assessor | 后端规则 |

## 5. 三通道分离（上下文工程）

按生命周期分三个层，**不要混在一个消息里**：

| 通道 | 内容 | 生命周期 | 谁消费 |
|---|---|---|---|
| ① 用户文本 | 学生说的话 | 永久（对话真值） | Tutor、Assessor |
| ② 回合观测（turn context） | 用时、尝试次数、停顿、纠音分数、情绪信号 | **瞬时**，推理时现算现注入 | 只有 Tutor |
| ③ 学生画像 | 基线、常错点、能力图谱 | 长期 | Adapter、Assessor、Tutor |

**核心规则：**

1. **不把工程数据拼进用户话里** —— 对话历史只存用户文本，保持干净；否则重放给 Assessor 时分不清"用户说的"和"系统测的"，且 token 浪费、事后无法修正。
2. **注入的是"解读后的信号"，不是原始数字** —— `3.2s` 对模型没意义，`"比基线慢 1.8 倍，可能卡住了"` 才有意义。
3. **解读用轻量规则/小模型现算**（前端计时 → 后端对照画像基线 → 输出结论），不让大模型每轮自己算。
4. **只放 top 3~5 个信号**，多了模型会忽略。

## 6. 基础消息格式（回合观测块）

每次 Tutor 响应前，以 system 消息插入观测块，不改动用户消息：

```
[系统观测]
- 本次答题用时 3.2s（学生基线 1.8s，偏慢 1.8 倍，可能卡住了）
- 尝试次数：2，首次拼错 "aple"，无提示
- 语音置信度 0.87

[用户]
apple
```

- 观测块作为独立 system 消息，插在用户消息前。
- 计算时机：前端/边缘实时算好（不得增加对话延迟），后端对照画像基线做解读。

## 7. 事件日志结构（供 Assessor 课后消费）

对话历史只存用户文本，原始信号单独落库：

```json
{
  "turn_id": "t-1024",
  "lesson_id": "L-007",
  "ts": "2026-08-10T10:00:03Z",
  "user_text": "apple",
  "latency_ms": 3200,
  "attempts": 2,
  "first_mistake": "aple",
  "hint_given": false,
  "audio_score": 0.87
}
```

Assessor 读的是事件日志（原始数据），Tutor 看到的是观测块（解读后信号）——同一数据源，两种形态。

## 8. MVP 范围（别一上来全上）

1. **只需要 2 个 Agent**：Tutor（实时）+ Assessor（课后异步）。Content Curator 先用人工/规则生成素材，Adapter 先手工调。
2. **信号先上 2 个**：答题用时 + 尝试次数，验证 Tutor 会不会用，再加停顿/情绪。
3. **Motivator 用规则实现**，不占 token。
4. **思考等级建议**：Tutor 陪练用 `low`（快），Assessor 用 `low`~`medium`，Adapter/Curator 用 `high`（想清楚再动手的活）。
