# AIlesson 课程引擎 · 需求文档 v0.7

> 把影视素材改造成「一集 = N 节课」的 AI 课程。
> 前身：《文盲英语_产品设计文档.md》《子策划01-多Agent协作》《子策划02-实时语音流水线》
> 本文档写**需求与验收**；实现决策与踩坑见 §10、§11。

**v0.3 的核心变化**：教学单位从「词」升级为「教学点（词 + 短语 + 句子）」。
原因见 §10.1 —— 这是首个真实用户实测后推翻的假设。

---

## 1. 形态定位

| 维度 | 旧 MVP（illit-english-mvp） | 现在 |
|---|---|---|
| 交互主体 | 点选刷题 | **仍以点选为主**，叠加语音 |
| 组织单位 | 用户自选 level + 批量 | **一节课**，脚本驱动，中间不做决策 |
| 教学单位 | 词 | **教学点 = 词 / 短语 / 句子** |
| 学习边界 | 一集 = 一个池子 | 一集 = N 节课，N 由自评决定 |
| 反馈 | 对/错 + 正确答案 | Tutor 答错讲解、课后报告 |
| 素材 | — | 完全复用，**数据层零改动** |

**核心原则：点选负责学会，开口负责记住和敢用。** 答题本地判定、零延迟；语音走旁路，失败不阻塞。

## 2. 目标用户（v0.3 明确）

**首个真实用户：大学毕业、CET-6 已过、但不会运用英语、词汇量一般。**

这个画像直接决定了 v0.3 的改造：他勾掉了 53 个词里的 48 个，但 28 个短语只会 5 个、
16 个句子只会 1 个。**「认识这个词」和「能张口说出这句」是两个维度**，只在词层分池
会把 90% 该学的内容筛掉。

次要用户：零基础学习者（词层仍是主体）、儿童（需拆成 15 分钟 × 2，本轮不做）。

## 3. 素材现状（E01 已清点）

`~/Claude/nowordenglish/illit-english-mvp/`

| 资产 | 数量 | 字段 |
|---|---|---|
| words | 53 | lemma, freq, audio(+slow), image, meaning_zh, skip_image |
| chunks | 28 | id, text, meaning_zh, audio_tts(+slow), image, **covers_words** |
| sentences | 16 | id, text_admin_only, meaning_zh, audio_tts(+slow), **audio_clip**(原片), image, **chunks**, **key_words**, time_start/end |
| distractors | 按词 | 每词 3 个难度合适的干扰项 |
| 整集视频 | 1 | episode.mp4 (5min) + episode.en.vtt |

10 集共 275 新词 / 166 chunk / 111 句，约 180MB。**引擎不新增任何字段。**

E01 教学点总数 = 53 + 28 + 16 = **97 个**。

## 4. 三层结构

```
集 (Episode)  = 53 词 / 28 短语 / 16 句 = 97 个教学点
  └─ 勾选自评 (三层各自分池)     ← 每集一次，3~5 分钟
  └─ 课 (Lesson) × N            ← N = 待学教学点 / 8
       └─ 环节 (Segment) × 16   ← 32 分钟
```

参数（代码里的常量，改动要同步本文档）：

| 常量 | 值 | 位置 |
|---|---|---|
| 一节课教学点 | 5~10，目标 8 | `packer3.MIN/MAX/TARGET_POINTS` |
| 掌握所需 streak | 2（双向） | `progress.MASTERY_STREAK` |
| 复习上限 | 9（三层合计） | `lesson3.MAX_REVIEW` |
| 抽检上限 | 每层 3 | `lesson3.MAX_SPOT_CHECK` |
| 计 streak 的环节 | 1,2,3,4,6,7,10,11 | `lesson3.STREAK_SEGMENTS` |

## 5. 功能需求

### FR-1 三层勾选自评（替代顺序分诊）

- **FR-1.1** 词 / 短语 / 句子**三层分别铺开勾选**，勾中 = 已会，其余进待学池。
- **FR-1.2** 三层的「会」标准不同，界面必须写明：
  - 词：听到能立刻反应出意思
  - 短语 / 句子：**能自己张口说出来**，只是「看懂」不算
- **FR-1.3** 每层按语义场 / 功能分组（LLM 生成），每组 8 个左右，支持「整组都会」批量勾。
- **FR-1.4** 底部实时显示三层待学数 + 预计节数。
- **FR-1.5** 结果落盘 `state.assessment`，含三层各自的 known/unknown/how。
- **FR-1.6** ~~提前终止~~ 已废弃（见 §10.2）。勾选是全览式的，没有终止一说。

### FR-2 抽检（防自评造假）

- **FR-2.1** 已勾会的条目在后续课里抽检（每节 ≤3 个词 + ≤3 个短语）。
- **FR-2.2** 抽检答错 → 打回待学池，当节转为重点。
- **FR-2.3** 优先抽检**和本节句子相关**的已会条目（马上要在语流里听到，最有意义）。

### FR-3 课程打包（按教学点计容量）

- **FR-3.1** 一节课容量：**5~10 个教学点**（目标 8），三层混排，比例由待学内容决定。
- **FR-3.2** 一节课要围绕**一个场景 / 一件事**，让课有主题。相关的词、短语、句子放一起。
- **FR-3.3** 尽量按剧情顺序推进（s01 → s16）。
- **FR-3.4** 每节起中文主题名，5~12 字，说人话（例："完蛋！妈妈快看见了赶紧打扫"）。
- **FR-3.5** 已勾会的内容不得出现在任何一节的重点里。
- **FR-3.6** 漏掉的条目摊进各节当「顺带点」（1 题、不跟读）。
- **FR-3.7** 打包结果按勾选组合缓存，同一组合不重算。

### FR-4 单节课编排（16 环节 · 32 分钟）

下表是**默认编排** `standard-16 v1` 的内容。编排本身是配置，见 FR-10。

| # | 环节 | 时长 | 内容 |
|---|---|---|---|
| 1 | 开场 + 复习 | 3.0 | 往期三层混合 ≤9 个，取较弱方向 |
| 2 | 抽检 | 1.0 | 已会条目 ≤6 个，答错打回 |
| 3 | 生词首触 | 2.0 | 听音选图 |
| 4 | 生词反向 | 1.5 | 看图选音 |
| 5 | 生词跟读 | 1.5 | |
| 6 | **短语听辨** | 3.0 | 听短语选图 |
| 7 | **短语反向** | 2.0 | |
| 8 | **短语跟读** | 2.5 | |
| 9 | 中场 | 1.0 | 原片切片，纯听不出题（降载） |
| 10 | **句子原声** | 3.5 | 用 audio_clip 原片切片 |
| 11 | **句子反向** | 2.0 | |
| 12 | **句子跟读** | 3.0 | |
| 13 | 混打 | 2.0 | 本节 + 复习打乱 |
| 14 | 错题重做 | 1.5 | 按教学顺序，含复习词 |
| 15 | 场景盲听 | 1.5 | 本节句子原声连放 + 自评（降载） |
| 16 | 收尾报告 | 1.0 | |

- **FR-4.1** 每个教学点至少 3 次曝光，形态不同：听辨 → 反向 → 跟读
  （词和短语还会在混打段再出一次；句子还会在盲听段再听一次）。
- **FR-4.2** **一节课可能一个生词都没有**（CET-6 用户常态），环节 3/4/5 为空时必须能正常跑完。
- **FR-4.3** 环节 9 / 15 为降载段，不出题。
- **FR-4.4** 任一环节可中断续上；**卡序必须确定性可重建**（见 §10.5）。
- **FR-4.5** 句子必须用 `audio_clip` 原片切片，不用 TTS —— 目标是听懂真实语流。
- **FR-4.6** 短语和句子的选项用**中文释义列表**，不用图片（图片区分度不够）；
  且和词一样 **4 选 1**——本节条目不足 4 个时从全集补足（2 选 1 蒙对率一半，
  1 个条目时只剩唯一选项等于没考）。
- **FR-4.7** 上课页使用**横屏 iPad 课堂布局**（课程应用惯用的横屏形态）：
  顶部为课堂标题 / 16 环节进度轨 / 卡片进度与对错统计；主区为**左教具、右作答**双栏；
  常驻静音按钮；触屏竖屏时给「请横过来」旋转提示。手机等窄屏降级为可滚动单栏，不阻断上课。

### FR-5 掌握度与调度

- **FR-5.1** 三层都走双向 streak：听辨方向 ≥2 **且** 反向 ≥2 才算掌握（`MASTERY_STREAK=2`）。
- **FR-5.2** **课内不产生「已掌握」**：每方向只出 1 题，streak 只到 1。掌握发生在后续课的复习环节。不为报告好看凑数。
- **FR-5.3** 只有环节 1/2/3/4/6/7/10/11（首触 + 反向 + 复习 + 抽检）计 streak。
  跟读（5/8/12）练产出、混打（13）重做（14）是巩固，都不计；但**答错仍要清零**。
- **FR-5.4** 复习出题方向取该条目**较弱的那一向**（否则单向永远升不到掌握）。
- **FR-5.5** 复习池排序：错得多的优先，然后是「离掌握最近的」。

### FR-6 语音层（旁路）

| 位置 | 实现 | 延迟 | 状态 |
|---|---|---|---|
| **答错讲解** | LLM，藏在「看正确答案」的间隙 | 宽松 | ✅ |
| 开场 / 环节过渡 / 收尾 | 预合成 TTS | — | ⬜ 未接 |
| 连对 3 次夸奖 | 预合成池随机 | 即时 | ⬜ 未接 |
| 卡住引导（20s 不动） | 收窄到 2 选 1 | 即时 | ✅（无语音） |
| 跟读评分反馈 | 本地 wav2vec2 + 预合成 | 300ms | ⬜ 未接 |
| 课后小结 | LLM 一次生成 | 无所谓 | ✅ |

- **FR-6.1** Tutor 闭嘴规则（硬约束）：答错一定说；环节切换一定说；连对基本不说；**每题都说 = 禁止**。
- **FR-6.2** 常驻静音按钮，静音后课程完整走完。
- **FR-6.3** 同一时刻只准一个声音。
- **FR-6.4** 语音层任何失败都不得阻塞答题主路径。

### FR-7 用户系统（MVP 无密码）

课程高度个性化 —— 每个人的待学池、掌握度、课堂数据都不一样，必须分用户存。
MVP 阶段只有几个人测试，**不做密码/登录**。

- **FR-7.1** 能力只要三件：创建用户、删除用户、选择用户。
- **FR-7.2** 用户 id 由名字生成 slug + 随机后缀，**必须能安全当目录名**
  （名字含 `/`、`..`、空格都不能污染路径）；显示名保留原样。
- **FR-7.3** 第一个用户自动选中；删除当前用户后自动切到下一个，没人了则为 None。
- **FR-7.4** 删除用户连同其学习状态和课堂数据一起删（不可恢复，前端要确认）。
- **FR-7.5** **LLM 缓存不分用户**，全局共享。词表分组是全集共享的；打包结果按
  「待学池内容」哈希，两个人勾出同样的池子可以复用。分用户会白烧钱。
- **FR-7.6** 没有选中用户时，涉及学习数据的接口返回 409，不得静默写到别处。
- **FR-7.7** 老的单用户 `data/state.json` 自动迁移到第一个用户（名为「我」），
  迁移后移走原文件避免重复迁移。
- **FR-7.8** **空会话不得覆盖已有进度**（见 §10.12）。

存储布局：

```
data/
  users.json                   用户名册 + 当前选中
  users/<uid>/state.json       学习状态（勾选、课程表、进度）
  users/<uid>/history.jsonl    每节课的课堂数据
  cache/                       LLM 缓存 —— 全局共享，不分用户
```

### FR-8 课堂数据记录

- **FR-8.1** 每节课收课时追加一条记录到 `history.jsonl`：题量、正确率、一次答对数、
  三层各学几个、盲听自评、需复习项、打回项、当次掌握项。
- **FR-8.2** JSONL 追加写（只增不改，天然抗并发），坏行跳过不影响整份历史。
- **FR-8.3** 用途：后续按真实表现调整教学（难度、复习强度、选材方向）。
  **本轮只记录，还没有消费方。**

### FR-9 课后报告

- **FR-9.1** 内容：三层各学几个 / 一次答对数 / 需复习项 / 盲听自评 / 打回项 / 下节预告。
- **FR-9.2** **按三层分别描述**，不能笼统说「N 个词」（见 §10.3）。
- **FR-9.3** **不得声称「已掌握」**（FR-5.2 的必然结果）。
- **FR-9.4** **一律显示人看得懂的内容，不露内部 id**（见 §10.4）。
- **FR-9.5** 复习项逐行列出，超过 8 项折叠。

### FR-10 教具与编排（v0.7）

一节课不是一段写死的流程，而是由**教具**按**编排**拼起来的。

- **FR-10.1** **教具**是一等对象，每件声明四项：交互形态（答题 / 跟读 / 被动播放 /
  自评 / 报告）、适用哪几层、**需要哪些素材**、是否产生对错。
  当前 7 件：听音选图、听音选义、看义选音、跟读、看片段、场景盲听、课后报告。
- **FR-10.2** **环节** = 一件教具的一次实例化 + 内容来源（本节正课 / 跨节复习 /
  抽检 / 混打 / 错题 / 降载）。FR-4 那张 16 环节表就是默认编排的内容。
- **FR-10.3** 「这一环计不计 streak」「这一环算不算首触」是**环节属性**，
  不是散落在代码里的环节序号判断。
- **FR-10.4** 编排带 `id` + 版本号，随快照落盘。**版本不匹配时不许重建课堂**，
  见 §10.15。
- **FR-10.5** 学习者看到的教具名和操作提示由教具声明，前端不自己拼 ——
  同一件教具在任何环节的说法必须一致。
- **FR-10.6** 加一件复用已有交互形态的教具，前端不用改（渲染按交互形态分派）。

### FR-11 内容完备度矩阵（v0.7）

教具声明了素材需求，就能算出「这一集哪些教学点能跑哪些教具」。

- **FR-11.1** 按「教学点 × 教具」给出可跑 / 不可跑，不可跑要说明**缺哪个素材**。
- **FR-11.2** 给出**缺口清单**，按影响条目数排序 —— 这是内容生产的待办。
- **FR-11.3** 默认只审当前编排真正用到的教具。报「短语缺配图」没有意义 ——
  编排里短语走听音选义，本来就不用图。
- **FR-11.4** `audio_clip` 指向 TTS 文件的**不算原片切片**。字段非空不等于素材到位，
  这条判据是 FR-4.5 能不能满足的唯一检验（见 §10.16）。
- **FR-11.5** 词的 `skip_image`（抽象词有意不配图）要和「漏了配图」区分开，
  不能报成缺口。

### FR-12 课程计划检查器（v0.7）

课程表是 `pack_course(自评)` 的函数值。要判断 AI 组得对不对，**必须能同时看到输入**。

- **FR-12.1** 并排给出：自评（三层各勾了什么）、听力探测（问了什么 / 答了什么 /
  校准出的阈值）、动态挑选（来源是探测还是启发式、挑出多少）、课程表（N 节、每节的点）。
- **FR-12.2** 标出 `fallback` —— 那表示 LLM 分组失败、用了机械划分。
- **FR-12.3** 可把任一节展开成**卡序**，按环节分组，并给出卡序的可变输入
  （复习选择 / 抽检选择 / 方向选择）—— 那三项是 §10.5 的落盘对象。
- **FR-12.4** 只读，且不得影响进行中的课堂。
- **FR-12.5** 不露内部 id（§4）：`s07` 要显示成句子原文。

## 6. LLM 使用约定

MVP 阶段**追求效果上限，不考虑成本**。以下环节明确用 LLM，不用规则兜底：

| 用途 | 时机 | 思考 | 实测耗时 |
|---|---|---|---|
| 三层清单分组 | 集级，一次 | 关 | 5~16s |
| 课程打包 | 每种勾选组合一次 | 开 | 13~40s |
| 答错讲解 | 课中，每次答错 | 关 | ~2s |
| 课后小结 | 课末，一次 | 关 | ~6s |

网关：`https://model.zhenguanyu.com`，凭证从 `~/.pi/agent/auth.json` 读
（**用 `zgy` provider，不用 `zgy-ds` 付费 key**）。Anthropic 路径只认 `x-api-key`。

**规则兜底只在 LLM 完全不可用时启用**，且不缓存兜底结果（下次该重试）。

## 7. 非功能需求

- **NFR-1** 答题判定本地完成，0 网络依赖。
- **NFR-2** 语音链路端到端 < 2s（已实测 1.65s）；跟读反馈 < 300ms。
- **NFR-3** LLM 结果按输入缓存复用。
- **NFR-4** 素材数据层零改动，直接读 illit-english-mvp 的 JSON 和 assets。
- **NFR-5** 模块依赖**单向**：契约层谁都读、它谁都不读；教研不读学习者数据
  （内容生产要能预生成）；教室端不依赖组课（它只吃课程契约）。由测试守。
- **NFR-6** 开发流程 **TDD**：先写测试再写实现。LLM 逻辑用 FakeLLM 断言结构与约束，不断言文案。

## 10. 需求变更记录（推翻过的假设）

### 10.1 教学单位：词 → 教学点（v0.3，实测推翻）

**原假设**：一节课教 6 个生词，短语和句子作为词的「配套」出现。

**实测**：CET-6 用户勾掉 48/53 个词，只剩 5 个生词 → 打包出 **1 节课**。但他不会的
26 个短语和 16 个句子被完全忽略了 —— 而 `it's only X`、`oh goodness me`、
`look at the mess you're in` 正是他要学的。

**改为**：教学点 = 1 词 / 1 短语 / 1 句，一节课 5~10 个点。短语和句子升级为一等
教学点（各有首触/反向/跟读）。同一勾选下从 1 节变 5 节，43 个教学点。

### 10.2 分诊：顺序问答 → 铺开勾选（v0.2→v0.3）

**原设计**：53 个词一题一题问「会/不会」，连续 5 个「不会」提前终止；为防误判，
出题顺序由 LLM 排成难度打散。

**推翻原因**：对有词汇量的用户，53 次点击是纯浪费；铺开勾选 3 分钟完事，还能横向
比较，判断更准。提前终止和难度打散**都是为顺序问答服务的**，一并废弃 ——
连带省掉 35s 的 LLM 排序调用。

已删除：`diagnosis.py`、`packer.py`、`lesson.py`、`course.py` 及其测试。
（留着带测试的死代码比删掉更糟。）

### 10.3 报告口径必须分三层

实跑发现 3 词 + 5 短语 + 2 句被写成「今天学了 10 个词」。三层混排后
「N 个词」是错的口径，改为 `learned_desc()` 分别描述。

### 10.4 报告不得露内部 id

实跑发现报告写「下次要复习：s16 guess_what weve_been_doing」，用户看不懂。
加 `CourseSession3.label_of()`，一律转成 `guess what` /
`Let's clean up quickly before mommy sees the mess.`。

### 10.5 卡序必须确定性可重建

**缺陷**：复习条目的**选择**（`pick_review`，读 last_at/streak）和**出题方向**
（`weaker_direction`，读 streak）都是实时算的。上课过程中这些值在变，restore 时
重算会得到另一副牌 → **续上错位到别的卡**。

**修法**：选择和方向在建课时定死，随快照落盘（`review_picked` / `spot_picked` /
`dir_picked`）。这类「卡序依赖可变状态」的 bug 值得专门写回归测试。

### 10.6 复习必须补「较弱方向」

复习永远出听辨方向时，反向永远停在 1，**词永远升不到掌握，间隔重复形同虚设**。

### 10.7 只有 8 个环节计 streak

混打段重复计 streak 会让课内凑满掌握（虚假掌握）。跟读练产出不算识别。
但巩固环节**答错仍要清零** —— 不计不等于把错误藏起来。

### 10.8 掌握需要 2~3 次复习，不是 1 次

一节课给复习项 1 题，双向达标至少需要 2 次复习。验收口径是「机制会收敛」
而非「两节课就掌握」。

### 10.9 短语约束是软的

`MIN_CHUNKS=2` 硬校验会把 LLM 逼到重试耗尽 → 退规则兜底 → 主题名变「第1组」。
**丢掉语义场内聚和主题名的损失比少一个短语大得多。** 改为：提示词里把「只需 1 个词
的短语」摊开（E01 有 10 个），并且重试到底仍有瑕疵时保留 LLM 划分。

### 10.10 其他实现修正

- chunk 由代码三档推导，不让 LLM 指定（模型给的常含本节没教的词）
- 复习池排序按「离掌握的距离」，否则只学过 1 次的顺带词会抢在正课词前
- 错题重做要含复习词（那恰恰最该重做），且按教学顺序不按发现顺序
- `first_try_correct` 只统计新内容首触，否则数字虚高
- 卡住收窄提示 8s → 20s（成人听两遍原声就超了）

### 10.11 环境提醒

- `.venv` 曾因基础 Python（`~/.local/opt/python-3.12.13-standalone`）被删而损坏。
  用 `uv venv --python 3.12` 重建，依赖走阿里云镜像。
- 端口 8770 在 macOS 被 `sharingd`(dpap) 占用，默认用 **8791**。

### 10.12 空会话不得覆盖已有进度

**缺陷**：切用户时会先 `save()` 当前会话。如果当前会话是「进程刚起、还没载入」
的空态，就会用空数据把盘上的进度清掉 —— **静默毁掉真实学习数据**。

**修法**：`Store._is_blank()` 判断会话是否什么都没发生（无 assessment、无 plan、
无完成课、无进行中的课），空态遇到已存在的文件就不写。

这类「保存空状态」的 bug 在单用户时代不会暴露（没有切换动作），加多用户才出现。

### 10.13 上课页：手机竖屏列表式 → 横屏 iPad 课堂式（v0.5）

**原形态**：上课页沿用 480px 手机布局，题目从上到下排成一列。实跑体验是
「在网页上刷题」，不像上课，也不符合 iPad 上课程应用惯用的横屏形态。

**改为**：上课页独立为横屏课堂外壳（`body.classing`）：顶部课堂标题 +
16 环节进度轨 + 卡片进度与对错统计；主区左教具（图 / 声）、右作答双栏；
常驻静音按钮；触屏竖屏时显示旋转提示。窄屏（手机横放）降级为可滚动单栏，
只是兜底，不改变「横屏 iPad 课堂」的默认形态。

### 10.14 答题卡交互缺陷修复（v0.6，脚本实跑全流程发现）

用 API 脚本完整走了一遍 Peppa 16 环节课（36 卡）和 Friends 真实存档课（61 卡），
除了下面四个，其余环节、素材 URL、暂停/续上全部正常：

1. **听音选图直接暴露答案** —— a2i 卡的 `image` 就是正确选项的图，而前端左栏
   无条件展示 `c.image`，等于把答案放在题面上。改为：a2i 作答前左栏只放声音，
   作答后再展示图片做确认（i2a 的图是题干、短语/句子的图是场景教具，不受影响）。
2. **看图选音没法先试听** —— i2a 点选项立即作答，只能听到自己选的那个。
   改为：选项内加独立 🔊 试听按钮（`stopPropagation` 不触发作答），点选项本体
   才是作答。提示语改为「先点 🔊 试听选项，再点选项作答」。
3. **短语/句子经常只有 2 选 1** —— 干扰项只从本节条目池取，一节 2 个短语就是
   2 选 1（1 个时只剩唯一选项）。改为从全集补足 4 个，与词卡同策略
   （`lesson3._fill_choices`）。
4. **🐢 慢速按钮是假的** —— Friends 词卡 `audio_slow` 与常速是同一文件，
   点了没区别。改为没有独立慢速音频就不渲染该按钮。
5. **选项图片被裁切** —— 横屏课堂里选项格会被拉成宽矩形，而选项图都是方图，
   `object-fit: cover` 把上下边裁掉，选图题等于题目坏了。改为 `contain`
   完整展示（选图题的图就是题干本身，必须全貌可见）。

这些缺陷的机制都写在单元测试里（`test_web_lesson_ui.TestCardInteraction`、
`test_lesson3.TestChoicePool`），防止回退。

### 10.15 编排可配则必须版本化（v0.7）

**原假设**：把 16 环节从代码抽成配置，是纯重构，行为不变。

**推翻原因**：卡序是**确定性重建**的 —— 快照不存卡，只存重建输入（§10.5），
牌靠建课逻辑重算。这个设计的前提是编排恒定。编排一旦可编辑，上周的快照拿这周改过的
编排去 restore 会重建出**另一副牌**：续上错位到别的卡，而且不会报错、不会崩，
只是学生突然在做一道不该出现的题。这比 §10.5 那次更隐蔽 —— 那次至少卡序长度变了。

**改为**：编排带 `id` + 版本号，随快照落盘。版本不匹配时**拒绝重建课堂**，
并把「哪一节、到第几张、原来是哪版编排」报给前端，让用户选重开。
不许静默重算，也不许静默丢进度 —— 课程表和掌握度都要留着。

**改编排 = 换教材。** 动了默认编排的任何一环，同一轮就把 `version` 升掉。

### 10.16 字段非空 ≠ 素材到位（v0.7，矩阵上线第一天抓到）

**原假设**：判断素材齐不齐，看 lesson JSON 里对应字段有没有值就够了。

**推翻原因**：完备度矩阵第一次跑出来报 Friends「三层全齐、零缺口」，与已知事实矛盾
（逐字稿没时间轴，拿不到原片切片）。查下去发现 `friends_lesson.py` 把
`audio_clip` 填成了 `audio_tts` —— 字段非空，内容是合成音。

**改为**：`audio_clip == audio_tts` 时不计入 `audio_clip`。这条判据是 FR-4.5
（句子必须用原片切片）能不能满足的唯一检验。改完矩阵报出 76 个句子全缺原片切片。

**推论**：完备度检查要检验**内容**，不是字段存在性。同类风险还有：占位图、
空白音频、机翻释义 —— 这些都能骗过「字段非空」。

### 10.17 教学单位的三个维度不能挤在一个字段里（v0.7）

**原假设**：`Card.kind` 一个字符串够描述一张卡（`a2i` / `i2a` / `chunk` /
`sentence` / `shadow` / `passive` / `assess` / `report`）。

**推翻原因**：这些值混了三件事 —— 交互形态、哪一层、哪个方向。`chunk` 同时表示
「选择题」和「短语层」。后果是运行时里出现 `kind in ("a2i","i2a","chunk","sentence")`
这种想说「这是道选择题」却只能穷举的判断；加一种卡要同时改运行时、前端渲染表、
前端提示表三处；而「这种卡需要什么素材」根本没有落点，只存在于一句代码注释里。

**改为**：拆成 `tool`（教具 id）+ `domain`（层）+ `direction`（方向），
交互形态从教具表查，不存副本。素材需求成为教具的声明字段 —— FR-11 的矩阵才有了依据。

## 12. 老友记内容线（并行进行中）

Peppa 一集 5 分钟 / 53 词；Friends 一集 22 分钟 / 300+ 句 / 300+ 生词 ——
按 FR-3.1 的容量算要 **50 节课**，「一集 = N 节课」直接爆掉。所以要先切段 + 分级。

已有：`content/segment.py`（按词数切段，切点吸附换场边界）、`content/vocab_cefr.py`
（CEFR 归一）、`content/friends_lesson.py`（转成引擎认的 lesson JSON）、
`scripts/friends_*.py`（解析 / 索引 / 试切 / 分级）、CEFR-J + Octanove 词表。
S1E1 已产出 160 词 / 114 短语 / 76 句。

**接通引擎的两个待解问题：**

1. **逐字稿没有时间轴** —— 拿不到 `audio_clip`。现在转换器填的是 TTS，
   完备度矩阵按 FR-11.4 判定为缺原片切片：**76 句全缺**。而 FR-4.5 要求句子必须用
   原片（听懂真实语流是产品核心）。可选：强制对齐（whisper + 原片音轨）／
   找带时间轴的字幕源。
2. **一集 = 多段，每段 = N 节课** —— 现有三层结构（集 → 课）要多加一层「段」，
   或把「段」当成引擎眼里的「集」。后者改动小，倾向后者。

词层和短语层的素材是齐的（矩阵零缺口），所以句子层通了就能上课。
