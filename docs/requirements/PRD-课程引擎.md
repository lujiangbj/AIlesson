## 1. 形态定位

| 维度 | 旧 MVP（illit-english-mvp） | 现在 |
|---|---|---|
| 交互主体 | 点选刷题 | **仍以点选为主**，叠加语音 |
| 组织单位 | 用户自选 level + 批量 | **一节课**，脚本驱动，中间不做决策 |
| 教学单位 | 词 | **教学点 = 词 / 短语 / 句子** |
| 学习边界 | 一集 = 一个池子 | 一集 = N 节课，N 由自评决定 |
| 反馈 | 对/错 + 正确答案 | Tutor 答错讲解、课后报告 |
| 素材 | — | 完全复用，**数据层零改动** |

**核心原则：点选负责学会，开口负责记住和敢用。** 答题本地判定、零延迟；语音走旁路，失败不阻塞。

## 2. 目标用户（v0.3 明确）

**首个真实用户：大学毕业、CET-6 已过、但不会运用英语、词汇量一般。**

这个画像直接决定了 v0.3 的改造：他勾掉了 53 个词里的 48 个，但 28 个短语只会 5 个、
16 个句子只会 1 个。**「认识这个词」和「能张口说出这句」是两个维度**，只在词层分池
会把 90% 该学的内容筛掉。

次要用户：零基础学习者（词层仍是主体）、儿童（需拆成 15 分钟 × 2，本轮不做）。

## 4. 三层结构

```
集 (Episode)  = 53 词 / 28 短语 / 16 句 = 97 个教学点
  └─ 勾选自评 (三层各自分池)     ← 每集一次，3~5 分钟
  └─ 课 (Lesson) × N            ← N = 待学教学点 / 8
       └─ 环节 (Segment) × 16   ← 32 分钟
```

## 5. 功能需求

### FR-1 三层勾选自评（替代顺序分诊）

- **FR-1.1** 词 / 短语 / 句子**三层分别铺开勾选**，勾中 = 已会，其余进待学池。
- **FR-1.2** 三层的「会」标准不同，界面必须写明：
  - 词：听到能立刻反应出意思
  - 短语 / 句子：**能自己张口说出来**，只是「看懂」不算
- **FR-1.3** 每层按语义场 / 功能分组（LLM 生成），每组 8 个左右，支持「整组都会」批量勾。
- **FR-1.4** 底部实时显示三层待学数 + 预计节数。
- **FR-1.5** 结果落盘 `state.assessment`，含三层各自的 known/unknown/how。
- **FR-1.6** ~~提前终止~~ 已废弃（见 §10.2）。勾选是全览式的，没有终止一说。

### FR-2 抽检（防自评造假）

- **FR-2.1** 已勾会的条目在后续课里抽检（每节 ≤3 个词 + ≤3 个短语）。
- **FR-2.2** 抽检答错 → 打回待学池，当节转为重点。
- **FR-2.3** 优先抽检**和本节句子相关**的已会条目（马上要在语流里听到，最有意义）。

### FR-3 课程打包（按教学点计容量）

- **FR-3.1** 一节课容量：**5~10 个教学点**（目标 8），三层混排，比例由待学内容决定。
- **FR-3.2** 一节课要围绕**一个场景 / 一件事**，让课有主题。相关的词、短语、句子放一起。
- **FR-3.3** 尽量按剧情顺序推进（s01 → s16）。
- **FR-3.4** 每节起中文主题名，5~12 字，说人话（例："完蛋！妈妈快看见了赶紧打扫"）。
- **FR-3.5** 已勾会的内容不得出现在任何一节的重点里。
- **FR-3.6** 漏掉的条目摊进各节当「顺带点」（1 题、不跟读）。
- **FR-3.7** 打包结果按勾选组合缓存，同一组合不重算。

### FR-4 单节课编排（16 环节 · 32 分钟）

| # | 环节 | 时长 | 内容 |
|---|---|---|---|
| 1 | 开场 + 复习 | 3.0 | 往期三层混合 ≤9 个，取较弱方向 |
| 2 | 抽检 | 1.0 | 已会条目 ≤6 个，答错打回 |
| 3 | 生词首触 | 2.0 | 听音选图 |
| 4 | 生词反向 | 1.5 | 看图选音 |
| 5 | 生词跟读 | 1.5 | |
| 6 | **短语听辨** | 3.0 | 听短语选图 |
| 7 | **短语反向** | 2.0 | |
| 8 | **短语跟读** | 2.5 | |
| 9 | 中场 | 1.0 | 原片切片，纯听不出题（降载） |
| 10 | **句子原声** | 3.5 | 用 audio_clip 原片切片 |
| 11 | **句子反向** | 2.0 | |
| 12 | **句子跟读** | 3.0 | |
| 13 | 混打 | 2.0 | 本节 + 复习打乱 |
| 14 | 错题重做 | 1.5 | 按教学顺序，含复习词 |
| 15 | 场景盲听 | 1.5 | 本节句子原声连放 + 自评（降载） |
| 16 | 收尾报告 | 1.0 | |

- **FR-4.1** 每个教学点至少 3 次曝光，形态不同：听辨 → 反向 → 跟读
  （词和短语还会在混打段再出一次；句子还会在盲听段再听一次）。
- **FR-4.2** **一节课可能一个生词都没有**（CET-6 用户常态），环节 3/4/5 为空时必须能正常跑完。
- **FR-4.3** 环节 9 / 15 为降载段，不出题。
- **FR-4.4** 任一环节可中断续上；**卡序必须确定性可重建**（见 §10.5）。
- **FR-4.5** 句子必须用 `audio_clip` 原片切片，不用 TTS —— 目标是听懂真实语流。
- **FR-4.6** 短语和句子的选项用**中文释义列表**，不用图片（图片区分度不够）。

### FR-5 掌握度与调度

- **FR-5.1** 三层都走双向 streak：听辨方向 ≥2 **且** 反向 ≥2 才算掌握（`MASTERY_STREAK=2`）。
- **FR-5.2** **课内不产生「已掌握」**：每方向只出 1 题，streak 只到 1。掌握发生在后续课的复习环节。不为报告好看凑数。
- **FR-5.3** 只有环节 1/2/3/4/6/7/10/11（首触 + 反向 + 复习 + 抽检）计 streak。
  跟读（5/8/12）练产出、混打（13）重做（14）是巩固，都不计；但**答错仍要清零**。
- **FR-5.4** 复习出题方向取该条目**较弱的那一向**（否则单向永远升不到掌握）。
- **FR-5.5** 复习池排序：错得多的优先，然后是「离掌握最近的」。

### FR-6 语音层（旁路）

| 位置 | 实现 | 延迟 | 状态 |
|---|---|---|---|
| **答错讲解** | LLM，藏在「看正确答案」的间隙 | 宽松 | ✅ |
| 开场 / 环节过渡 / 收尾 | 预合成 TTS | — | ⬜ 未接 |
| 连对 3 次夸奖 | 预合成池随机 | 即时 | ⬜ 未接 |
| 卡住引导（20s 不动） | 收窄到 2 选 1 | 即时 | ✅（无语音） |
| 跟读评分反馈 | 本地 wav2vec2 + 预合成 | 300ms | ⬜ 未接 |
| 课后小结 | LLM 一次生成 | 无所谓 | ✅ |

- **FR-6.1** Tutor 闭嘴规则（硬约束）：答错一定说；环节切换一定说；连对基本不说；**每题都说 = 禁止**。
- **FR-6.2** 常驻静音按钮，静音后课程完整走完。
- **FR-6.3** 同一时刻只准一个声音。
- **FR-6.4** 语音层任何失败都不得阻塞答题主路径。

### FR-7 用户系统（MVP 无密码）

课程高度个性化 —— 每个人的待学池、掌握度、课堂数据都不一样，必须分用户存。
MVP 阶段只有几个人测试，**不做密码/登录**。

- **FR-7.1** 能力只要三件：创建用户、删除用户、选择用户。
- **FR-7.2** 用户 id 由名字生成 slug + 随机后缀，**必须能安全当目录名**
  （名字含 `/`、`..`、空格都不能污染路径）；显示名保留原样。
- **FR-7.3** 第一个用户自动选中；删除当前用户后自动切到下一个，没人了则为 None。
- **FR-7.4** 删除用户连同其学习状态和课堂数据一起删（不可恢复，前端要确认）。
- **FR-7.5** **LLM 缓存不分用户**，全局共享。词表分组是全集共享的；打包结果按
  「待学池内容」哈希，两个人勾出同样的池子可以复用。分用户会白烧钱。
- **FR-7.6** 没有选中用户时，涉及学习数据的接口返回 409，不得静默写到别处。
- **FR-7.7** 老的单用户 `data/state.json` 自动迁移到第一个用户（名为「我」），
  迁移后移走原文件避免重复迁移。
- **FR-7.8** **空会话不得覆盖已有进度**（见 §10.12）。

存储布局：

```
data/
  users.json                   用户名册 + 当前选中
  users/<uid>/state.json       学习状态（勾选、课程表、进度）
  users/<uid>/history.jsonl    每节课的课堂数据
  cache/                       LLM 缓存 —— 全局共享，不分用户
```

### FR-8 课堂数据记录

- **FR-8.1** 每节课收课时追加一条记录到 `history.jsonl`：题量、正确率、一次答对数、
  三层各学几个、盲听自评、需复习项、打回项、当次掌握项。
- **FR-8.2** JSONL 追加写（只增不改，天然抗并发），坏行跳过不影响整份历史。
- **FR-8.3** 用途：后续按真实表现调整教学（难度、复习强度、选材方向）。
  **本轮只记录，还没有消费方。**

### FR-9 课后报告

- **FR-9.1** 内容：三层各学几个 / 一次答对数 / 需复习项 / 盲听自评 / 打回项 / 下节预告。
- **FR-9.2** **按三层分别描述**，不能笼统说「N 个词」（见 §10.3）。
- **FR-9.3** **不得声称「已掌握」**（FR-5.2 的必然结果）。
- **FR-9.4** **一律显示人看得懂的内容，不露内部 id**（见 §10.4）。
- **FR-9.5** 复习项逐行列出，超过 8 项折叠。

## 10. 需求变更记录（推翻过的假设）

### 10.1 教学单位：词 → 教学点（v0.3，实测推翻）

**原假设**：一节课教 6 个生词，短语和句子作为词的「配套」出现。

**实测**：CET-6 用户勾掉 48/53 个词，只剩 5 个生词 → 打包出 **1 节课**。但他不会的
26 个短语和 16 个句子被完全忽略了 —— 而 `it's only X`、`oh goodness me`、
`look at the mess you're in` 正是他要学的。

**改为**：教学点 = 1 词 / 1 短语 / 1 句，一节课 5~10 个点。短语和句子升级为一等
教学点（各有首触/反向/跟读）。同一勾选下从 1 节变 5 节，43 个教学点。

### 10.2 分诊：顺序问答 → 铺开勾选（v0.2→v0.3）

**原设计**：53 个词一题一题问「会/不会」，连续 5 个「不会」提前终止；为防误判，
出题顺序由 LLM 排成难度打散。

**推翻原因**：对有词汇量的用户，53 次点击是纯浪费；铺开勾选 3 分钟完事，还能横向
比较，判断更准。提前终止和难度打散**都是为顺序问答服务的**，一并废弃 ——
连带省掉 35s 的 LLM 排序调用。

已删除：`diagnosis.py`、`packer.py`、`lesson.py`、`course.py` 及其测试。
（留着带测试的死代码比删掉更糟。）

### 10.3 报告口径必须分三层

实跑发现 3 词 + 5 短语 + 2 句被写成「今天学了 10 个词」。三层混排后
「N 个词」是错的口径，改为 `learned_desc()` 分别描述。

### 10.4 报告不得露内部 id

实跑发现报告写「下次要复习：s16 guess_what weve_been_doing」，用户看不懂。
加 `CourseSession3.label_of()`，一律转成 `guess what` /
`Let's clean up quickly before mommy sees the mess.`。

### 10.5 卡序必须确定性可重建

**缺陷**：复习条目的**选择**（`pick_review`，读 last_at/streak）和**出题方向**
（`weaker_direction`，读 streak）都是实时算的。上课过程中这些值在变，restore 时
重算会得到另一副牌 → **续上错位到别的卡**。

**修法**：选择和方向在建课时定死，随快照落盘（`review_picked` / `spot_picked` /
`dir_picked`）。这类「卡序依赖可变状态」的 bug 值得专门写回归测试。

### 10.6 复习必须补「较弱方向」

复习永远出听辨方向时，反向永远停在 1，**词永远升不到掌握，间隔重复形同虚设**。

### 10.7 只有 8 个环节计 streak

混打段重复计 streak 会让课内凑满掌握（虚假掌握）。跟读练产出不算识别。
但巩固环节**答错仍要清零** —— 不计不等于把错误藏起来。

### 10.8 掌握需要 2~3 次复习，不是 1 次

一节课给复习项 1 题，双向达标至少需要 2 次复习。验收口径是「机制会收敛」
而非「两节课就掌握」。

### 10.9 短语约束是软的

`MIN_CHUNKS=2` 硬校验会把 LLM 逼到重试耗尽 → 退规则兜底 → 主题名变「第1组」。
**丢掉语义场内聚和主题名的损失比少一个短语大得多。** 改为：提示词里把「只需 1 个词
的短语」摊开（E01 有 10 个），并且重试到底仍有瑕疵时保留 LLM 划分。

### 10.10 其他实现修正

- chunk 由代码三档推导，不让 LLM 指定（模型给的常含本节没教的词）
- 复习池排序按「离掌握的距离」，否则只学过 1 次的顺带词会抢在正课词前
- 错题重做要含复习词（那恰恰最该重做），且按教学顺序不按发现顺序
- `first_try_correct` 只统计新内容首触，否则数字虚高
- 卡住收窄提示 8s → 20s（成人听两遍原声就超了）

### 10.11 环境提醒

- `.venv` 曾因基础 Python（`~/.local/opt/python-3.12.13-standalone`）被删而损坏。
  用 `uv venv --python 3.12` 重建，依赖走阿里云镜像。
- 端口 8770 在 macOS 被 `sharingd`(dpap) 占用，默认用 **8791**。

### 10.12 空会话不得覆盖已有进度

**缺陷**：切用户时会先 `save()` 当前会话。如果当前会话是「进程刚起、还没载入」
的空态，就会用空数据把盘上的进度清掉 —— **静默毁掉真实学习数据**。

**修法**：`Store._is_blank()` 判断会话是否什么都没发生（无 assessment、无 plan、
无完成课、无进行中的课），空态遇到已存在的文件就不写。

这类「保存空状态」的 bug 在单用户时代不会暴露（没有切换动作），加多用户才出现。
