# AI英语课策划-子策划02：实时语音流水线优化

> 配套文档：《AI英语课策划.md》《子策划01-多Agent协作设计.md》
> 本子策划聚焦：ASR / LLM / TTS 三环节如何配合，让对话流畅自然。

## 1. 核心认知：三者是「重叠流水线」，不是「串行」

❌ 错误理解：听完整句话 → LLM 想完 → TTS 合成完 → 播放（三个延迟全累加）

✅ 正确理解：三者**边产出边传递**，只有「衔接延迟」没有「叠加延迟」：

```
用户说"apple..."
  ├─ ASR 边听边出 partial 结果 ──────────────┐
  │                                          │
用户停顿 → VAD 判定回合结束 → ASR final       │
  └──────────────┬───────────────────────────┤
                 ▼                           │
  LLM 开始生成（短回复）→ 第一个 token 出来     │
                 │                           │
                 ▼                           │
  TTS 边合成边播放 ← 第一句话 chunk 就到了      │
```

**只要每段之间只等「第一个 chunk」，总延迟可以压到单次 LLM 响应之下。**

## 2. 延迟预算（目标 vs 实测）

| 环节 | 预算目标 | **本机实测（M3 Pro）** |
|---|---|---|
| ASR（对话理解） | 300~500ms | **340ms**（whisper-base 本地）|
| LLM（快模型+关思考） | 200~600ms | **560~940ms**（deepseek-flash 流式）|
| TTS（turbo流式+连接复用） | 300~400ms | **370ms**（Minimax）|
| **端到端（说完→开口）** | <1.5s | **1.65s** |

教学场景能接受 0.5~1s 响应间隙，关键是**不能忽快忽慢**（不稳定比慢更伤体验）。

## 3. 三环节各自优化

### ASR（识别）—— 详见第 8 节实测
- 流式识别 + VAD 快速端点（检测到停顿即判定回合结束，不等 800ms 静音）
- 教学热词表（apple、sentence… 加权，更快更准）
- **本地 whisper-base（0.34s）已满足对话理解，0 成本**
- 识别错了让 Tutor 用「你是说 X 吗？」自然纠错，比追求 100% 准确更划算
- **发音评分必须音素级模型**（wav2vec2），whisper 文本比对不可行（见第 8 节踩坑）

### LLM（思考）—— 详见第 9 节实测
- Tutor 用快模型 + **直接关闭思考**（`thinking.disabled`）：首 token 从 3.37s 降到 0.56s
- 强制短回复（prompt 规定「一句话夸奖 + 一句引导」）→ 首 token 快 + TTS 快
- 上下文压缩（会话历史 compaction）
- 预生成可缓存内容（开场白、夸奖语模板化）

### TTS（合成）
- 流式合成（chunk 边生成边播，TTFB 压到几百 ms）
- 常用短语预合成缓存（夸奖/过渡/激励语提前合成，命中≈0）
- 短句优先（回复拆短句，第一句先播）

## 4. TTS 选型：Minimax（已实测）

### API 配置

- **域名**：`https://api.minimaxi.com/v1/t2a_v2?GroupId={GroupId}`（国内版；`api.minimax.chat` 为国际版）
- **模型**：`speech-2.6-turbo`（低延迟，面向实时）
- **音色**：`yfd-xiaokui-06`（少儿向女声，适合教育产品）
- **流式**：payload 加 `"stream": true`，响应为 SSE，chunk 里取 `data.audio`
- **音频**：MP3 / 32kHz / 128kbps / 单声道

### 实测数据（2026-08，本机）

**走公司代理（proxy-aws-us.zhenguanyu.com，美国AWS）时：**

| 指标 | 耗时 |
|---|---|
| TLS 握手 | 2.0s ← 瓶颈 |
| 首字节 | 2.5s |
| 流式首包 | 2.7~3.2s |

**绕过代理直连时：**

| 指标 | 耗时 |
|---|---|
| TLS 握手 | 0.16s |
| 首字节 | 0.22s |
| 流式首包（热连接）| **0.25~0.36s** |

**结论：Minimax 国内服务本身很快，热连接下首包 0.25~0.4s，完全够实时教学。**

### ⚠️ 踩坑记录：延迟假象的根源

1. **公司代理 `proxy-aws-us.zhenguanyu.com`（美国AWS）**：所有流量绕道美国，TLS 硬吃 2s，导致 TTS 看起来慢 10 倍
2. **DNS fake-ip 劫持**（198.18.0.0/15 保留段，Clash/Surge 类工具）：DNS 正常解析但流量实际全走代理

**排障启示：线上 TTS 慢，先查网络路径/代理，别先怀疑 TTS 服务商。**

## 5. 流式调用代码示例（Minimax + speech-2.6-turbo）

```python
import json, time, requests

GROUP_ID = "1728712324971237986"
API_KEY  = "Bearer {token}"

url = f"https://api.minimaxi.com/v1/t2a_v2?GroupId={GROUP_ID}"
headers = {
    "Authorization": API_KEY,
    "Content-Type": "application/json",
    "Accept": "application/json, text/event-stream"   # SSE
}
payload = {
    "model": "speech-2.6-turbo",
    "text": "Good job! Now let's try the word apple.",
    "stream": True,                                    # 关键：流式
    "timbre_weights": [{"voice_id": "yfd-xiaokui-06", "weight": 1}],
    "voice_setting": {"voice_id": "yfd-xiaokui-06", "speed": 1, "pitch": 0, "vol": 1},
    "audio_setting": {"sample_rate": 32000, "bitrate": 128000, "format": "mp3", "channel": 1},
    "language_boost": "auto",
}

# 必须用 Session 复用连接（TLS 只付一次，热连接首包 0.3s）
s = requests.Session()
s.trust_env = False    # 绕过系统代理（生产环境视部署而定）
with s.post(url, headers=headers, json=payload, stream=True, timeout=60) as r:
    for line in r.iter_lines(decode_unicode=True):
        if line and line.startswith("data:"):
            chunk = json.loads(line[5:])
            audio = chunk.get("data", {}).get("audio")
            if audio:
                # 将 audio（base64）喂给播放器，边收边播
                pass
```

## 6. 架构建议

```
┌───────────── 端侧（本地方案已验证） ────────┐
│  ASR：whisper-base（对话理解 0.34s）         │
│  发音评分：wav2vec2 音素模型 + espeak（0.4s）│
│  VAD / 端点检测                             │
│  预合成缓存（夸奖/过渡语）                   │
└──────────────┬──────────────────────────────┘
               │ WebSocket/RTC
┌──────────────▼──────────────────────────────┐
│  实时会话引擎（状态机编排）                   │
│  VAD→ASR→LLM→TTS 的流水线调度                │
│  后端保持 TTS 长连接复用                     │
└──────────────┬──────────────────────────────┘
               │
┌──────────────▼──────────────────────────────┐
│  云端：LLM（deepseek-flash 关思考）           │
│       + Minimax 流式 TTS                     │
└─────────────────────────────────────────────┘
```

**工程要点：**

1. **ASR/发音评分全程本地 0 成本**（whisper-base + wav2vec2，M3 CPU 实时率 0.04~0.6x），只有 LLM 和 TTS 走云端
2. **后端代理 + 长连接复用**：TLS 只付一次，热连接首包 0.3s；**不要浏览器前端直连**（每次新连接冷启动 0.9s+）
3. **状态机放中间层**：负责「谁说完了、谁先播」的调度，别让三个服务互相裸聊
4. **预合成缓存兜底高频套路语**（夸奖/引导/激励，命中率可能 50%+，延迟≈0）

### 8.2 本地免费方案（已实测，0 成本）

| 方案 | 模型 | 识别耗时 | 输出 | 用途 |
|---|---|---|---|---|
| **whisper-base** ⭐ | faster-whisper | **0.34s**（1.8s 音频）| 完整文本 | 对话理解（喂 LLM）|
| whisper-small | faster-whisper | 0.98s | 完整文本 | 精度优先 |
| **wav2vec2-base-960h** | facebook | 0.57s | 大写无标点 | 快速文本 |
| **wav2vec2 音素模型** | lv-60-espeak-cv-ft | **361ms（10s 音频）**| IPA 音素 | **发音评分** |

### 8.3 发音评分：音素级方案（免费替代腾讯智聆）

**为什么 whisper 不行**：whisper 是语义识别，会把发音错误自动「纠正」成正确单词（mawning→morning），文本比对恒得满分——**文本比对做不了发音评分**。

**正确方案（已验证）**：

```
学生录音 → wav2vec2 音素模型（facebook 开源，~300MB）
                 ↓ 实际音素（IPA）
参考文本 → espeak-ng + phonemizer（brew 安装）
                 ↓ 参考音素（IPA）
音素序列比对（difflib）→ 评分 + 差异音素反馈
```

实测效果：

| 音频 | 实际音素 | 评分 | 反馈 |
|---|---|---|---|
| 标准发音 | `ɡʊd mɔːɹnɪŋ...` | **100/100** | 完全标准 ✓ |
| mawning（缺 r 音）| `ɡʊd mɔːnɪŋ...` | **97.9/100** | ⚠ 缺 `ɹ` 音 |

**对比商业方案**：腾讯智聆口语评测 9.9 元/万次（按次，≤20 词=1 次）、后付费 0.005 元/次。本地方案 0 元、无限次、音素级定位，demo/教学反馈足够；需要「流畅度/完整度」等多维度时再上商业版。

### 8.4 踩坑：whisper 不能做发音评分

whisper 语义识别自动纠正发音错误，`test_bad.wav`（故意读错 mawning）被识别成 `morning`，文本比对得 100 分。**发音质量必须音素级模型**。

## 9. LLM 思考优化实测（deepseek-v4-flash）

**关键发现：deepseek 是推理模型，默认带思考（reasoning），会显著拖慢首 token。**

| 配置 | 首token | 思考量 | 结论 |
|---|---|---|---|
| 默认 | **3.37s** | 1195 字符 | 太慢 ❌ |
| reasoning_effort=low | 1.94s | 572 | 一般 |
| reasoning=false | 1.29s | 306 | 较快 |
| **thinking: {"type":"disabled"}** | **0.56s** | **0** | ⭐ 快 6 倍 |

**另外的坑**：`max_tokens` 太小（如 60）会被 reasoning 吃光，导致回答根本没输出（收到 DONE 但 content 为空）。需加大 max_tokens（≥400）并关思考。

**结论：Tutor 简单回应场景直接关思考（`thinking.disabled`），这是对延迟影响最大的一项优化。**

## 10. 端到端链路实测（学生说完 → Tutor 开口）

| 环节 | 耗时 | 方案 |
|---|---|---|
| ① ASR 识别 | **0.34s** | whisper-base（本地 CPU）|
| ② LLM 首 token | 0.56~0.94s | deepseek-flash + thinking disabled |
| ③ TTS 首包 | **0.37s** | Minimax turbo 流式（直连）|
| **全链路** | **1.65s** | 教学场景可用 ✅ |

优化空间（目标 1.3s）：
1. TTS 预合成缓存（夸奖/引导语命中≈0）
2. ASR 换更小模型或流式 partial 提前触发 LLM
3. LLM 冷热连接差异（0.56~0.94s 波动）
